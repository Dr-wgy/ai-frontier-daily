# AI早报关键词去重与聚合改造方案

## 📋 项目改造方案：基于关键词的新闻去重与聚合

### 🎯 改造目标

1. **解决内部重复**：每日新闻中相似主题的新闻合并为新闻集
2. **解决跨日重复**：基于关键词历史记录，过滤与昨日高度相似的新闻
3. **保持摘要质量**：LLM 对新闻集进行汇总摘要，而非单条新闻摘要

---

## 📐 整体架构设计

### 数据流程改造

```
ingested.jsonl (RSS原始)
    ↓
filtered_ranked.json (筛选+分类+关键词提取)
    ↓
[新增] clustered.json (关键词聚类+历史去重)
    ↓
summary.json (LLM新闻集摘要增强)
    ↓
briefing.md (最终简报)
```

---

## 🔧 详细改造设计

### 1️⃣ 数据模型层改造 (`utils/domain.py`)

**新增 `NewsCluster` 类**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `cluster_id` | string | 集群唯一标识 |
| `keywords` | List[str] | 关键词列表（LLM提取） |
| `items` | List[FilteredItem] | 包含的新闻条目 |
| `merged_relevance` | float | 合并后的相关性（取最高） |
| `merged_hot_level` | float | 合并后的热度（取最高） |
| `main_section` | string | 主板块 |
| `sub_section` | string | 子栏目 |
| `rank` | int | 集群排名 |

**属性方法**：
- `title`: 取最相关新闻的标题
- `urls`: 所有新闻的URL列表
- `sources`: 所有新闻的来源列表（去重）
- `merged_summary`: 取最相关新闻的摘要

**修改 `FilteredItem` 类**：

新增字段：
| 字段 | 类型 | 说明 |
|------|------|------|
| `keywords` | List[str] | 关键词列表（LLM提取，2-5个） |

---

### 2️⃣ 筛选排序模块改造 (`filter_rank.py`)

**核心改造点**：

1. **LLM 响应解析**：提取 `keywords` 字段
2. **关键词聚类**：相似关键词的新闻合并为集群
3. **历史去重**：基于历史关键词记录过滤重复新闻

**新增类**：

#### `KeywordClusterer`
负责基于关键词相似度对新闻进行聚类：

| 方法 | 说明 |
|------|------|
| `cluster_by_keywords()` | 对新闻列表进行聚类 |
| `_calculate_keyword_similarity()` | 计算两组关键词的相似度（Jaccard相似度） |
| `_merge_keywords()` | 合并多条新闻的关键词 |

#### `HistoricalKeywordDedup`
负责基于历史关键词记录进行去重：

| 方法 | 说明 |
|------|------|
| `load_recent_keywords()` | 加载最近N天的关键词历史 |
| `save_today_keywords()` | 保存今日的关键词历史 |
| `dedup_by_history()` | 基于历史关键词去重 |

---

### 3️⃣ 提示词模板改造 (`prompts/filter_ranker.md.j2`)

**新增 `keywords` 字段**：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `keywords` | string[] | 是 | 关键词列表（2-5个），提取新闻的核心实体、技术名词、公司名、产品名等 |

**关键词提取规则**：
- 提取新闻中的核心实体、技术名词、公司名、产品名
- 每条新闻提取 2-5 个关键词
- 关键词应具有代表性，能反映新闻的核心主题
- 避免提取过于宽泛的词（如"技术"、"发布"、"公司"）

---

### 4️⃣ 摘要模块改造 (`summarize.py`)

**改造为处理新闻集**：

| 改造点 | 说明 |
|--------|------|
| 输入格式 | 从单条新闻改为新闻集（cluster） |
| 提示词参数 | `news_json` → `clusters_json` |
| 摘要逻辑 | 对新闻集进行汇总摘要，综合集群内所有新闻的关键信息 |

---

### 5️⃣ 摘要提示词改造 (`prompts/summarizer.md.j2`)

**改造为处理新闻集**：

| 改造点 | 说明 |
|--------|------|
| 输入单元 | 从单条新闻改为新闻集（cluster） |
| 标题生成 | 反映集群整体主题，而非单条新闻 |
| 概要生成 | 综合集群内所有新闻的关键信息 |
| 响应字段 | `source_index` → `cluster_id` |

---

### 6️⃣ 配置文件改造 (`config/config.yaml`)

**新增去重配置**：

```yaml
# 新增：关键词聚类配置
keyword_similarity_threshold: 0.7    # 关键词相似度阈值（用于聚类）
max_items_per_cluster: 5             # 每个集群最多新闻条数

# 新增：历史关键词去重配置
history_dir: "data/keyword_history"  # 历史关键词存储目录
recent_days: 3                        # 历史去重天数
history_similarity_threshold: 0.6    # 历史关键词相似度阈值
```

## 📊 改造影响分析

### 优势

1. **解决内部重复**：通过关键词聚类，相似主题的新闻自动合并
2. **解决跨日重复**：基于历史关键词记录，过滤与昨日高度相似的新闻
3. **提升摘要质量**：LLM 对新闻集进行汇总，提供更全面的信息
4. **保持多样性**：每个板块限制集群数量，避免单一主题刷屏

### 挑战

1. **关键词提取质量**：依赖 LLM 准确提取关键词
2. **聚类阈值调优**：需要根据实际效果调整相似度阈值
3. **历史存储管理**：需要定期清理过期的历史关键词文件

## 📝 核心设计思想

### 内部去重机制
```
关键词提取 → 相似度计算 → 聚类合并 → 新闻集
```

### 跨日去重机制
```
今日关键词 → 历史关键词对比 → 相似度判断 → 过滤重复
```

### 摘要生成机制
```
新闻集输入 → LLM汇总 → 综合摘要 → 输出
```

## 📌 关键注意事项

1. **关键词提取质量**：需要在提示词中明确关键词提取规则，确保 LLM 提取高质量的关键词
2. **阈值调优**：相似度阈值需要根据实际数据进行调优，建议从较宽松的阈值开始
3. **存储管理**：需要定期清理过期的历史关键词文件，避免存储空间占用过大
4. **向后兼容**：改造过程中需要保持与现有代码的兼容性，逐步引入新功能
